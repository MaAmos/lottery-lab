# 自动采集、核对和训练：一次配置，日常使用网页

运行方式：GitHub Actions 定时运行 Python → 恢复已核实的历史数据 → 对新浪和500的近期号码逐期比对 → 上传有来源证据的号码、核对旧记录 → 有新开奖时重新拟合实验模型 → 通过受保护接口发布到 Cloudflare D1 → 网页读取新快照。无需保持电脑在线，无需每期重新部署网页。

福彩、体彩官网会拦截 GitHub 托管环境（实测403/567）。因此保留已采集的官方历史元数据，新增号码必须由新浪和500的期号、日期、前后区号码全部一致才接纳；两个发布方并不等于已直接核验官网。新增周边字段保持缺失，不冒充官方资料。来源冲突、落后或出现缺期时停止发布并保留旧模型。

`lottery_lab/bootstrap/history.json.gz` 保存6458期公开历史数据及76份原始来源响应，`manifest.json` 记录哈希与覆盖范围；不含密钥。首次运行或缓存被回收时从此包恢复，后续通过 Actions Cache 保留增量 SQLite 和原始响应。最近100期与已保存历史必须有重叠；长期停运超出近期窗口时需人工补档。普通更新不再强制访问受限官网。

本项目已实现此流程；**只有你完成下方一次性配置并成功运行 Actions 后，线上自动更新才真正启用**。

## 1. 先部署新版 Worker 和数据库

按同目录的 [DEPLOY.md](DEPLOY.md) 部署完整包。本次已新建并初始化 `lottery-lab-fresh-20261026`，`DB` 绑定已填写新库ID `90e93795-a555-4fdc-80e0-de06d3a230ee`。在所属账号核对后继续部署；建表SQL可重复执行。新库不导入旧候选和旧模型记录。后续代码升级继续保持本次新库的ID；Worker名称和域名按实际部署目标设置。

确认 `https://你的域名/api/research` 返回 JSON。尚未启用 Actions 时，页面显示“部署时的初始快照”。只改包内 `model-report.json` 不会发布新模型。

## 2. 配置 Cloudflare 更新密钥

在部署包目录执行：

```sh
openssl rand -hex 32
npx wrangler secret put AUTO_UPDATE_TOKEN
```

第一条生成随机密钥。保存这串值，第二条提示输入时粘贴同一串值。它用于授权训练任务更新模型，不需要给 GitHub Cloudflare 账号 API Token。

密钥只放 Cloudflare Secret 和下面的 GitHub Actions Secret，不写进前端、源码或 `wrangler.json`。如果更换密钥，两边同时更新。

## 3. 把自动更新源码放入 GitHub 仓库

使用这次提供的 `lottery-automation-source-*.zip`，解压后进入包含 `.github`、`lottery_lab`、`vue-version` 和 `cloudflare` 的目录。它包含工作流、训练代码、初始参考快照、前后端源码和部署工具，不含本地训练数据或密钥。macOS Finder 默认不显示 `.github`，终端 `ls -a` 可查看。

在 GitHub 创建一个空仓库，可选择 Private；不要勾选初始化 README。随后在解压目录执行：

```sh
git init
git add .
git commit -m "Add automatic lottery data and model updates"
git branch -M main
git remote add origin https://github.com/你的用户名/你的仓库.git
git push -u origin main
```

使用 GitHub 已配置的凭据或 SSH 完成推送。若原项目已在 GitHub，直接把这些新增/修改文件提交至现有仓库默认分支即可，不必重新建仓库。

工作流文件必须位于默认分支的 `.github/workflows/lottery-update.yml`。不要只上传 ZIP 本身，也不要只上传 Vue 页面。

## 4. 添加两个 Actions Secrets

GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret：

| Name | Value |
|---|---|
| `LOTTERY_API_URL` | 完整站点源地址，例如 `https://lottery-lab.xxx.workers.dev`，不带 `/api` |
| `LOTTERY_AUTO_UPDATE_TOKEN` | 第2步保存的同一串随机密钥 |

仓库 Actions 如被禁用，先在 Actions 页面启用工作流。私有仓库的 Actions 分钟数、制品存储额度以自己的 GitHub 套餐为准。

## 5. 手动跑通一次

仓库 → Actions → **Lottery daily update** → Run workflow → 选择默认分支 → Run workflow。

任务会安装 Python/NumPy、执行数据与训练测试、恢复历史、采集近期号码并核对来源。首次即使没有新增期次，也会按新来源说明重新训练并激活D1；后续只有新期次才训练和发布。

成功后核对三处：

1. Actions 显示绿色；日志末尾是 `Initial D1 snapshot activated`、`No new official draw` 或成功发布的模型ID。
2. 网页点击“刷新状态”：显示“在线模型快照”、最近任务状态和发布时间。取得新期次时，截止期号应随之推进。
3. 在网页生成候选并下载。生成响应应包含 `saved: true`；“我的候选核对”出现本次记录。等对应日期官方开奖后再刷新，查看命中个数。

初次任务从随源码提供的压缩包恢复历史，联网只采集近期数据。原始响应、JSONL、报告、权重和冲突证据通过 Actions Artifacts 保留30天；无新增开奖的运行没有新训练报告。D1长期保存已发布模型、首次前瞻快照和候选核对结果。需要更长原始档案时，定期下载制品或调整保留策略。

## 6. 后续日常使用

定时检查的北京时间为每天 **22:30、23:30、次日07:30**。GitHub 的计划任务可能排队或延迟，后两次用于补抓晚公布/暂时失败的来源。Cloudflare 另有每天22:00的备用采集和核对，不负责训练。

日常只需打开网页，确认“截止期号”和任务状态，再生成候选。网页按钮不会重新训练。**有新开奖才训练**，同一期多次运行不会累加前瞻样本，也不会把已过期快照改成有效。

网页显示失败或长时间停在旧期号时，在 Actions 查看失败步骤，修复后点 Re-run jobs；来源暂时不可用时可等下一次定时重试。未成功发布前继续使用旧版，旧版过期后暂停生成。没有新开奖、休市或日期推迟时，按估计日期的旧记录保留待核对，不强行分配到其他日期或期号。

公开仓库长时间没有活动时，GitHub 可能自动停用定时工作流；以 Actions 页面提示为准。定时触发不是精确到分钟的保证。

## 7. 训练和检验的具体约束

- 首次历史划分固定：前200期预热，剩余60%训练、20%验证、20%测试；每日保持原区间和验证集选定的窗口/正则参数，不反复扩大测试集调参。
- 有新开奖后，用最新全量历史重拟合实验模型。周边字段至少滞后两期，并设置48小时隔离；省级新闻无法核实则保留缺失。
- 正式候选仍为均匀随机去重。自动训练不自动宣称“提高一等奖概率”，边际评分变好不能证明整注中奖优势。
- 上线后的检验，只使用服务实际发布时间早于目标日北京时间20:00的首次快照；每个彩种每个开奖日期一次。发布时间采用服务器时间，不接受训练脚本回填的时间。
- 开奖后核对每注红/前区、蓝/后区命中个数，并计算模型的 Brier / log loss。期号待确认的记录只在估计日期与官方日期一致、官方期号晚于数据截止期时核对。未核实规则版本的奖金不计算。
- 来源号码冲突、数据缺期、覆盖倒退、非法概率、冻结参数改变、并发版本冲突会中止发布。不同模型版本不可覆盖；发布和活动版本切换在D1事务中执行。

这些约束让系统持续积累可检查的实验结果，不保证预测优势。历史指标不会被当作上线后的新样本。

## 8. 故障对照

| 现象 | 处理 |
|---|---|
| API URL 设置错误 / 404 | 只填站点源地址，不附加 `/api`，确认部署的是完整 Worker 包 |
| HTTP401 | 两边密钥不一致，重新配置同一串值 |
| HTTP503 / 数据库暂不可用 | 核对 `DB` 绑定并运行新版 `npm run db:remote`；检查 Secret 是否已配置 |
| 采集阶段失败 | 看日志中的来源与HTTP状态；新浪/500更新不同步、号码冲突或缺期会停止发布，不能跳过校验强行训练 |
| 元数据新闻补充失败 | 数字源有效时仍可训练，未核实字段保持缺失 |
| 发布HTTP409 | 活动模型已改变或官方号码发生冲突；重新运行读取当前版本，冲突需先核对来源 |
| 更新成功但前瞻样本为0 | 尚未等到首次发布后对应日期的官方开奖，属于正常情况 |
| 浏览器看不到旧候选 | 只记住当前浏览器最近20次ID；可用下载记录核对，清除浏览器数据会丢失本地ID |

代码升级才需要重新构建/部署Worker；普通开奖更新只发布D1模型快照。若要回退模型，需人工核对数据截止期和有效日期，不能仅回滚 Worker 就认为D1活动模型也已回退。
