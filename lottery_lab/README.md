# 彩票数据与训练流程

这里实现并实际运行了独立的历史数据采集、质量核对、模型训练、留出验证和候选生成。已补齐 GitHub Actions 后台自动更新；配置见 [自动更新步骤](../cloudflare/AUTOMATION.md)。Vue 首页优先读取D1的活动快照，未激活时使用初始快照。旧预测表不再充当训练集。

当前实验结果见 [实际训练报告](data/latest-report.md)，机器可读结果见 [report.json](data/latest-report.json)。本地原始响应、SQLite 和每次实验记录保存在 `lottery_lab/data/`，此目录默认不提交；可部署快照为 `vue-version/worker/src/generated/research.json`。

## 运行

在项目根目录执行，要求 Python 3.11+、Node 22.12+、curl：

```sh
python3 -m venv .venv
.venv/bin/pip install -r lottery_lab/requirements.txt

# 首次全量抓取；再次运行默认使用可恢复缓存。
.venv/bin/python lottery_lab/pipeline.py collect

# 最近20期大乐透新闻：仅接收分布合计与官方一等奖注数一致的记录。
.venv/bin/python lottery_lab/pipeline.py enrich --limit 20

# 重训并冻结测试报告、权重、5注候选及可部署快照。
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 .venv/bin/python lottery_lab/pipeline.py train --seed 20261026

# 开奖后更新，必须刷新分页缓存，防止新一期挤动分页边界。
.venv/bin/python lottery_lab/pipeline.py collect --refresh
.venv/bin/python lottery_lab/pipeline.py enrich --limit 20
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 .venv/bin/python lottery_lab/pipeline.py train --seed 20261026
```

每次训练生成新的 `data/runs/<run_id>/`，包含报告、冻结评估权重、全历史重拟合权重及候选。SQLite `model_runs` / `prediction_runs` 同时记录数据指纹和运行信息。`latest-report` 与部署快照指向最新一次结果，历史运行目录不会覆盖。

本地使用两个终端：

```sh
# 终端1，项目根目录
.venv/bin/python lottery_lab/pipeline.py serve

# 终端2
cd vue-version/client
npm run dev
```

打开 Vite 输出的本地地址。开发请求通过 Vite 代理到 `127.0.0.1:8787`，不会请求原线上 API。生产环境默认同源；前后端不同域时通过 `VITE_API_BASE_URL` 配置 Worker 地址。

本地轻量 API 不连接 D1，新生成记录需点“下载本次记录”保存；训练时的候选已经落入 SQLite 和运行目录。生成、保存或下载均不表示已购票。

## 数据收集与质量

1. 双色球官方福彩接口：号码、各奖级注数和单注奖金、销量、开奖后奖池、原始中奖分布文字。
2. 大乐透官方体彩接口：号码、各奖级（含追加与派奖）、销量、开奖后奖池、官方公告链接。
3. 新浪开奖列表：补齐双色球早期号码，核对两种彩票重叠期的号码与开奖日期。
4. 新浪近期大乐透新闻：保留原文片段和原始页面，只接受能完整解释官方一等奖注数的省级分布；省份归属不清、追加与基本注数无法对齐时留空。它是次级报道，不会覆盖官方奖金或销量。

2026-10-26 首次实采的覆盖：

| 字段 | 双色球 | 大乐透 |
|---|---:|---:|
| 历史号码 | 3,519期，2003001—2026122 | 2,939期，2007001—2026121 |
| 官方来源号码 | 2,080期 | 2,939期 |
| 各奖级与奖池 | 2,080期 | 2,939期 |
| 销量 | 2,080期 | 1,541期 |
| 可解析省级分布 | 2,062期 | 最近20期中9期 |
| 已核实具体中奖网点 | 0 | 0 |

大乐透早期有650期奖池字段返回0且销量为空，尚不能确认这些0是否为历史回填占位值。原始0保留并打上 `pool_zero_unverified` 标记，训练时按缺失处理；其余2,289期奖池值纳入训练。原始字段存在不等于已经核实其历史真实性。

核对了各来源返回总数、重复期号、年度内期号连续性、号码范围/数量/唯一性以及跨来源冲突。当前数据范围内没有期号缺失或号码冲突；这不是对未来期号或缺失元数据完整性的保证。来源可能修订历史数据，原始快照保留供复查。

`sources` 保存 URL、采集时间、原始内容 SHA256；`observations` 保留每个来源观察，`draws` 保存优先采用的官方记录；`prize_tiers` / `winner_regions` 独立存储。金额使用 Decimal 转为整数分，空值、`---`、`-1` 保留 NULL，真实0保留0。派奖说明保留在原始响应中；基础奖与派奖分别记录，避免同一个 group 覆盖两条奖级。

若跨来源号码冲突，采集失败并写入 `data/conflicts.json`，训练也拒绝继续。应核实原始证据并解决数据问题，再归档冲突文件，不应直接忽略。

具体网点没有可用的统一完整接口，本次未伪造或用省份代替网点。`winner_outlets` 已预留来源链接、网点编号、地址、发布时间字段，但目前没有已核实记录。网点抓取仍需按各省公开公告逐个建设，不属于已完成的数据覆盖。

## 具体训练与预测思路

### 预测目标

号码是无序集合，分别预测每个前区/红球、后区/蓝球号码下一期被选中的边际概率。双色球均匀基线为红球 `6/33`、蓝球 `1/16`；大乐透为前区 `5/35`、后区 `2/12`。

不把排好序的第一个球当成第一个独立分类目标，也不把模型分数转成“中奖置信度”。边际概率之积不是整注一等奖概率。

### 四组对照

- `uniform`：均匀随机，作为必须超过的基线。
- `frequency`：历史频率，候选窗口30/100/300期，加入50期强度的均匀先验平滑；窗口用验证集选择。
- `history_logistic`：带L2正则的逻辑回归，在同一球区内共享参数；特征为20/60/200期平滑频率、遗漏、前两期是否开出、号码位置、奇偶、上期邻号。正则强度候选0.01/0.1/1，用验证集选择。
- `metadata_logistic`：加入销量、奖池、一等奖注数与奖金的log值、完整省级分布的集中度和缺失标记，并与频率、遗漏等号码特征交互。相同的奖池值对所有号码一样，直接塞进去不能区分号码，所以显式构建交互项。

标准化均值、方差只在训练段计算。输出通过logit偏移投影，使一个球区所有边际概率之和等于实际出球数。

历史元数据至少滞后两期，另要求开奖日期后满48小时才允许使用；当期销量、一等奖注数、分布等绝不进入当期预测特征。历史公告没有提供可核实的实际发布时间，因此这只是保守的事后可用时间代理，尚不是完全通过发布时间审计的前瞻实验。省级列表与一等奖总注数对不上时，集中度特征按缺失处理。

### 验证方法与本次结论

前200期预热，之后按时间60%训练、20%验证、20%测试。训练集学习参数，验证集选窗口和正则参数，最后测试集只用于检查泛化。测试时滚动使用此前已开奖的号码构造特征，模型参数保持冻结；没有用打乱后的随机切分。

用 Brier 和边际 log-loss 评分，越低越好；对逐期“模型分数减均匀基线分数”做长度10期、2,000次的分块bootstrap，报告99%差值区间。它处理了部分时间相关性，但不证明平稳性，也不代替多轮独立验证。

同时对每个测试期、每种模型固定生成5注不同的基本单式，预算均为10元，固定随机种子，统计红/蓝球命中与整注一等奖命中。加权抽样使用边际值作为顺序抽样权重，不声称这些权重就是整注分布。一等奖极少，不能通过数百期的0次命中判断模型之间谁更会中大奖。

本次双色球测试664期，大乐透测试548期。周边信息模型在两种彩票的验证集上最好，但在测试集上都未超过均匀基线；频率模型也更差。历史模型的微小正负差异未形成稳定优势。详细数值和区间已写入实际报告。

因此正式候选仍使用均匀随机。实验模型可在页面手动选择，但不会因一小段回测获胜而自动接管默认生成。测试集从现在起已被看过；后续根据结果改特征时，应将本次测试段视为已知历史，新增未看过的未来开奖用于下一轮验证，不能继续把它当成“全新测试集”。

### 候选与一等奖目标

正式生成只保证号码合法、整注去重、预算透明。取消和值、奇偶、连号等硬筛选，不复制历史整注作为模板，也不强迫每注球号低重叠。整注不同就有不同的一等奖覆盖，球号部分相同本身不减少覆盖的整注数量。

在公平独立开奖假设下，同一期5注不同单式的一等奖概率是双色球 `5/17,721,088`，大乐透 `5/21,425,712`。历史号码、销量或中奖网点不会自动改变这一概率。选号优化不能被说成突破这个边界。

日期仅按常规开奖星期估计，期号留空等待官方确认；节假日与停销须以公告为准。快照到估计开奖日北京时间20:00后拒绝继续生成，避免拿旧一期数据冒充下期。此保守截止时间不等于官方停售时间。

训练命令使用 Python `random`，API 使用 `mulberry32-v1`；下载记录带有各自引擎版本和种子，在同一个引擎内可复现，不保证跨引擎相同种子生成相同号码。每个运行保留模型ID、数据指纹、生成时间、数据截止期号和是否购票。

## 页面、API与部署范围

- 新首页展示数据覆盖、留出测试、实验模型、候选和下载记录；旧 `Home.vue` 保留为未挂载参考，旧小程序/云函数没有迁移。
- `/api/research` 读取D1活动快照（未激活时读部署初始快照）；`/api/backtest` 返回完整数据实验结果，不再运行旧的20期随机排名。
- `/api/predict` / `/api/predict-bundle` 生成基本单式，参数例如 `{"lotteryType":"dlt","count":5,"model":"uniform","seed":12345}`。每注2元，实验模型须显式选择。
- `/api/save-prediction` 旧保存接口停用；公开GET `/api/fetch-results` 不再写数据库。
- 定时采集改为每天北京时间22:00，把两个官方接口返回的全部最近30期追加至 `official_draw_snapshots`，不改写旧的NULL期号预测、不进行未核实奖金结算。超过30期的停机缺口应运行全量采集补齐。
- Cloudflare定时采集追加官方数据并核对新流程候选；GitHub Actions每日三次检查全量来源，有新开奖时冻结原测试边界和超参数，重拟合下期实验模型，通过认证接口发布到D1，页面无需重新部署。没有新开奖时不延长旧快照有效期。
- `/api/admin/*` 仅接受服务端更新密钥；模型版本不可覆盖，原子切换，发布前检查官方截止号码、概率合法性、数据倒退和协议改变。前瞻样本采用真实服务发布时间，每个彩种每个目标日期仅首次发布的快照进入核对。
- `/api/research-results` 根据当前浏览器记住的不可猜测运行ID读取候选与命中记录，不列出其他用户的全部候选。日期延期的记录保持待核对，不擅自归到其他期次；不计算未经规则审计的奖金。
